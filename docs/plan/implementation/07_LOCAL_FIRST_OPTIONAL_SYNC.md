# 07 — 联网应用、本地保存可选、按需云协作（2026-09-11 用户澄清）

状态：用户已确定产品方向；本文是对旧版“登录后离线缓存”的架构修订。用户随后澄清：用户通常仍会联网，重点是允许业务数据只保存在本地，而非承诺整个产品完全离线。此修订在相关冲突处优先于 01–06，既定 Swift/SwiftUI/GRDB、Fastify/PostgreSQL 技术栈不变。按后端优先推进，不能把此文中的协议/数据表当成已实现。

## 1. 产品默认与数据归属

- 应用按联网产品设计，账号、资料更新与在线功能正常保留。提供“仅本机保存”的数据存储选择；它不等于断开网络，也不自动启用云端家庭。账号登录要求由账号流程决定，不能用“本地保存”推导整个应用无需登录。GRDB 保存正式业务记录和本地附件，不能只保存待上传缓存；这些记录不因 30/90 天缓存窗口被清理。
- 本地手工录入、查看已有记录等适合本地执行的操作使用本地库，断网时保留其可用性。协作、云端 MCP、AI、OCR、在线资料更新不作离线承诺。旧文“病历/疫苗正式写必须在线”的云端权限/业务校验仍适用于已连接空间；只在本地保存的个人记录不应为保存而被迫上传。
- 多人协作、跨设备同步、云备份必须联网，并由用户主动启用相关空间的数据共享。云端 MCP 读取家庭记录需要联网、账户授权及该范围的云端数据；本地记录不会自动出现在 MCP。系统联网、登录、订阅、使用在线 AI 都不能自动开启全库同步。
- SQLite 继续用作 iOS 本地持久库。服务端数据库仍为 PostgreSQL；不恢复生产 SQLite，不引入 CloudKit 第二套同步。
- 区分 `localVaultId`（无需 userId 的本地空间）与 cloud binding。不得把“本地用户”伪装成已认证服务端 principal。

## 2. 客户端与服务端状态

客户端存储选择默认 localOnly；这只限制后台数据同步，不限制普通联网。可显式请求开启同步进入 enabling，完成账户/目标空间确认和服务端激活后才能 enabled；同步进度另行管理，只有首次同步真正完成后才能显示“已同步”。关闭进入 paused。enabling/paused/revoked 均不允许后台上传或拉取。失败不回退成自动同步。

服务端后续增加 DeviceSyncBinding：userId、installationId、localVaultId、familyId、status、generation、consentVersion、timestamps；必须验证真实 principal、installation ownership、家庭成员关系。generation 是持久化的单调整数，暂停、撤销、切账号/重新授权时递增，旧任务不能恢复有效。服务端不得接受客户端提交 status=active 自行解锁。

上传/拉取任务捕获 binding ID 与 generation；服务端在同一事务中校验 binding 为 active、generation 相等，再执行已有 command service。原生 REST 写入口与 sync 入口不能绕开这个条件。Web/MCP 仍使用各自真实 principal 和授权路径，不能让客户端伪造“我是 Web”绕过原生同步选择。

本轮先实现纯领域授权规则与客户端状态规则；持久化、端点和调度在 BE-02/BE-04/BE-05 与 IOS01–04 落地后才可对外使用。

账号与宝宝按多对多关联，详见 [08 账号与宝宝关系](08_ACCOUNT_BABY_RELATIONSHIPS.md)。家庭绑定通过不意味着能读取家庭内全部宝宝：同步导入、快照、feed、附件和 MCP 还需逐宝宝核对有效关联与权限。权限变化必须使相应缓存/快照失效，不能继续使用旧的家庭级授权结果。

## 3. 首次开启与重新开启

1. 解释上传范围、目标账号/家庭、附件大小和共享对象，用户明确确认。
2. 可新建云端家庭，也可选择已有且有写权限的家庭。只列目标，不默认混入现有家庭。
3. 创建 pending binding 和迁入计划。保留 local UUID；冲突的既有 ID 不覆盖，通过计划明确映射/跳过/冲突处理。local createdBy 只作来源元数据，不能冒充云端 actor。
4. 按稳定 importId + chunkId 幂等提交；每条数据经过领域校验与租户授权。记录成功 receipt/checkpoint；应用退出后可以恢复，重复提交不复制记录。
5. 只在用户确认范围的记录/附件完成后激活绑定。首次迁入不允许依赖普通 active sync API：专用 import 用 pending binding、明确批准的计划和代际校验；它只允许该计划的首次导入，不允许常规后台同步。
6. 初次快照与 change feed 复用 02 的 highWater/tail cursor，不另造第二套弱同步。激活响应丢失时查询绑定状态，不盲目再次创建。

## 4. 关闭同步、退出与撤销

关闭首先在本地停止发起新网络任务，并递增本地 operation epoch；迟到响应不改写新的活动空间。随后在联网时暂停服务端绑定、撤销该绑定的同步订阅。已被服务器提交的操作无法靠取消 URLSession 撤回，应在联网时通过幂等 receipt 对账并明确显示停止时刻。

关闭同步不会删除本地数据，也不会自动删除云端副本。云端副本删除是独立、可预览的操作。已有家庭中的其他成员可继续协作。重新开启需重新确认账号/空间；不能把旧队列投递到新账号或新家庭。

云端权限被撤销后，联网确认撤销时立即封锁该 cloud binding、停止同步并按既有权限规则清理云缓存。对完全离线设备无法即时远程收回其已下载数据；不得声称能做到。用户自己的纯本地空间不受云端成员移除影响，不自动把被撤销共享数据复制到新本地空间。

## 5. 本地保留、备份与分析

- 纯本地业务实体不应用云 feed retention；云 cursor 过期只重建云缓存，不删除 localOnly 正式记录。
- 按 vault 分区保存本地记录、附件、待迁入映射；账号切换不能复用另一个账号的绑定。Keychain 管理密钥，文件启用系统数据保护。
- 首发需本地导出/恢复（带 schemaVersion、附件 manifest/hash），以及清晰的设备丢失/卸载风险说明。用户手动导出不等于开启云同步；iCloud 系统备份是否包含本地数据必须作为独立可见设置，不能把“纯本地”解释为自动云备份。
- 本地提供确定性统计、时间轴与必要的版本化参考资料；计算规则用共享测试向量保持与服务端一致。在线分析结果显示来源和生成时间，离线缺少结果不生成假 AI 文案。

## 6. 在线功能是单独的选择

AI、OCR、语音转写、天气等需要联网的功能说明所发送的数据及处理方。用户主动请求、完成必要登录和该功能的数据发送确认后可使用，**不要求开启全库同步**，也不因此把其它记录上传。

后端在线分析请求采用独立的限量上下文/临时附件会话及留存策略，不以“先创建云端宝宝并上传整个历史”为前提；不得提供无鉴权/无限额度代理。返回结果在本地确认后落入本地业务库。持久 AI run 继续按服务器任务生命周期运行，但只保存本次授权上下文；客户端关闭同步不取消已经明确请求的 AI run，取消 AI 是单独动作。

## 7. 对执行顺序的修订

1. BOOT-02：先完成可构建工作区、隔离测试和 CI；不在这个阶段提供伪造的业务成功接口。
2. BE-01：把 cloud binding / 首次导入契约与 mode 能力补入 schema/inventory；本地资料库的创建不应依赖云同步初始化请求；产品是否要求账号登录是独立流程。
3. BE-02/03/04/05：持久绑定、代际校验、幂等 import、pause/revoke；校验与业务写处于同一事务。
4. iOS 的 IOS03 本地存储与 IOS02 账号初始化解耦；本地资料库使用 localVaultId。保留产品账号流程，登录成功不会创建云同步绑定；同步和在线服务分别检查所需授权。
5. IOS04 的同步引擎仅服务 opt-in 绑定；先做本地 CRUD 与重启不丢，再做导入/冲突/暂停/切账号。
6. 最终验收增加：选择本机保存后，普通联网/登录不上传业务库；已有本地记录断网仍可保存、查看并在重启后保留；协作/MCP 显示联网与数据授权条件；在线 AI 不启用全库同步；开启/暂停/重开与服务端代际冲突、迟到响应和多账号隔离。不要把尚未确认的“首次启动完全断网、无需账号”作为产品验收前提。

所有暂停/撤销和导入控制必须有真实数据库并发验证，不能只用本文配套的纯函数测试宣布同步已经实现。

## 8. iOS 必须展示的具体提示

| 功能 | 本地保存模式下的行为 | 提示重点 |
|---|---|---|
| 保存、编辑和查看本机记录 | 使用本机数据库；无需为保存而上传 | “记录仅保存在这台设备。联网不会自动上传。” |
| 家庭协作/跨设备 | 联网、登录，并确认要共享的云端空间 | “协作需要联网。开启后，所选空间的数据会与家庭成员共享。” |
| MCP 读取家庭记录 | 联网、OAuth 授权、对应范围的数据已在云端 | “MCP 只能访问你授权的云端数据；仅本机保存的记录不会自动上传。” |
| AI/OCR/语音等在线处理 | 用户单独确认本次发送内容；可保持本机保存模式 | “此功能需要联网，会发送你选中的内容，不会开启全部记录同步。” |

“开启协作/授权 MCP”不能作为隐式同意上传全部历史的开关。实现未完成时按钮明确说明尚未开放，不显示假的已启用状态。网络不可用提示与本地保存模式提示必须区分。
