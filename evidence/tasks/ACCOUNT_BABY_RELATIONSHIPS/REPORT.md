# 账号与宝宝多对多：服务端模型与复核

2026-09-11，工作分支 `codex/backend-storage-foundation`。在 BOOT-02 基础上落实用户新增要求：同人多宝宝、同宝宝多照护者。未提交、未部署。

实现状态为 `IMPLEMENTED_NOT_REVIEWED`；父侧已复核本轮纯模型、策略与执行规格。数据库表和业务端点仍未实现，不标记 BE-02 / BE-04 已验收。

## 已落地

- 明确 `User ↔ BabyMember ↔ Baby`，以 `(userId,babyId)` 唯一关联和 `(familyId,babyId)` 一致性约束表达多对多。
- 将家庭管理和宝宝数据权限分离：家庭 admin 没有 BabyMember 也不能读取宝宝记录；写入 / 管理采用当前家庭权限与宝宝权限的交集。
- 新增逐宝宝访问、成员管理、可见宝宝投影和最后可管理 admin 的纯策略及测试；旧的仅传 familyId 的记录写权限接口不再可用。
- FamilyMembership 明确要求 active 状态，同步绑定门禁同步拒绝邀请中或已撤销的家庭关联。JWT 或客户端 activeBabyId 不能作为宝宝权限来源。
- 计划 08 写入迁移回填、独立邀请范围、账号删除不级联共享宝宝、权限版本、按宝宝过滤 feed 和快照、索引 / 分页及原有锁顺序。02 / 03 / 06 / 07 与总计划入口已引用这项修订。

## 父侧复核与修复

1. 拒绝未知运行时家庭 / 宝宝 role，避免非 viewer 就能写入的漏洞。
2. 统一家庭只读权限和宝宝写权限的交集，避免同步门禁与记录策略得出相反结论。
3. 最后管理员保护同时核对其他候选者的有效家庭资格及非只读权限；名义上的 BabyMember admin 不一定能管理。
4. `loadedBaby` 明确要求事务内从数据库读取，不能接受客户端自己提交一份“已验证宝宝”。
5. 旧数据回填按旧成员与家庭中宝宝联结生成；不存在的旧 status 字段不能直接复制。新建家庭不自动创建宝宝，保留空家庭流程。
