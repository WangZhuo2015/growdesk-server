## 已发现并直接修复

1. **未知同步 operation 可能绕过写权限判断。** 独立子代理复现运行时传入 `delete` 返回 allowed。现有领域函数显式只接受 `pull` / `push`，同时拒绝未知家庭角色，并添加负测。TypeScript 类型不代替运行时拒绝。
2. **绑定替换后的旧请求。** 请求上下文增加 bindingId，与用户 / installation / vault / family / generation 一起核对，避免只靠相同代际误用另一条绑定。
3. **worker / scheduler 生命周期不可靠。** 未完成 Promise 不能保证 Node 常驻。实现者补了持有并清理的 timer、明确 idle 日志和真实子进程 SIGTERM 检查；没有声称已处理业务队列。
4. **依赖边界 regex 漏包子路径。** 已替换为 AST 提取 import / export / 动态 import / require 的模块字符串与相对路径检查，增加 `@prisma/client` 和跨层相对导入反例。它用于代码约束，不是恶意代码沙箱。
5. **未经冻结的业务契约。** 移除桌面硬件等错误范围契约；正式导出只保留本轮真实健康检查 schema，业务契约必须走 BE-01。
6. **测试与证据边界。** 集成测试纳入类型检查；新增正式 runner 的占端口、故障清理、实例冒用负测；补齐当前 REPORT 入口，避免后续 Agent 沿用“尚未安装”旧状态。

## 证据判断

父代理独立执行了根构建 / 类型 / lint / 单元测试、干净源码副本安装构建，以及隔离 PG / Redis 和 runner 负测。只读复核子代理另外执行了领域策略、guard、隔离基础设施和故障测试。具体结果见同目录 REPORT 和 `.txt` 输出。

纯同步策略的测试证明默认拒绝及上下文比较规则。真正的 installation ownership、持久 binding、同事务成员权限重读、暂停与并发写原子性，必须在 BE-02–05 用真实数据库证明。当前没有可被客户端调用的业务同步端点，也未测负载容量。
